Run scan

Two flavours of scan ship in the box: a passive audit of traffic you have already recorded, and an active scan that sends mutated requests at your target. Only run the active scan against systems you are authorised to test.

Passive scan

Replays no traffic. Audits every recorded request/response pair against the built-in rule set plus any enabled plugin rules and writes new findings to the project. Duplicate findings (same title + URL + evidence) are suppressed.

Active scan (sends traffic)

The active scanner sends mutated HTTP requests to the target. Probes are minimal markers, not weaponised exploits, but they will appear in the target's logs.

Scan profile

Scan profiles bundle intensity, probe budget, rate delay, redirect follow and wall-clock cap into a single named choice (matching Burp Suite's preset names). Pick a profile and the fields above act as overrides.

Authentication (optional)

Run a recorded login macro before the audit starts, keep the session warm by replaying it on demand, and (optionally) refresh CSRF tokens from the form's parent page before each write probe. Off by default. Credentials are never logged.

Preset

A preset picks which checks run. Custom uses the checkboxes below; the other presets ignore those checkboxes.

Intensity tiers

Tiers gate how aggressive the chosen checks are allowed to be. Explicit check selection (Customise checks) always wins, so a single check ticked by name still runs even if its tier is off.

⚠ Warning — Intrusive scans send time-based sleep probes, attempt to plant stored payloads, and may run parallel requests that look like an attack in target logs. Only enable this tier against systems you are authorised to test.
