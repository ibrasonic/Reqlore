New live capture

Define a request that returns a token (a session cookie, a CSRF field, a JSON value, anything you can point a regex at). Reqlore will re-fire the request in the background, extract the token from each response and store it. You can then analyse the live-collected pile with the same deep statistical randomness battery as the paste flow.

Capture configuration

Identification


* (required)

A short label shown in the captures list. The capture id is assigned by the database.

Request


* (required)

Used as the base URL when the raw request template uses a relative path. Scheme and authority come from this field; the path comes from the request line.


The engine used to send each capture request. Defaults to httpx; raw sends bytes exactly as typed (useful for malformed-header research).


* (required)

Raw HTTP request as it would appear on the wire. The Content-Length and Transfer-Encoding headers are recomputed on send. Newlines are normalised to CRLF automatically.

Token extractor


cookie: name of a cookie set by the response. header: name of a response header. regex: regular expression with one capture group, applied to the response body. json: dot-separated path into a JSON body (list indices are integers).


* (required)

Cookie name (e.g. SESSIONID), header name (e.g. X-CSRF-Token), regex (e.g. "token":\s*"([^"]+)"), or JSON path (e.g. data.session.token).

Run controls


* (required)

How many tokens to collect before stopping. 100 is a common baseline; FIPS-style confidence wants 1000+. Hard cap is 20000.


Politeness throttle. Set above zero to avoid tripping rate limits or generating obvious spikes in target logs.


Reserved for future use; current capture loop is single-flight to keep ordering deterministic. 1 is recommended.


Used when you press Analyse captured tokens on the detail page. Can be overridden at analysis time.
