2. Re-sign & forge

Paste your own PKCS8 PEM, or use Generate attacker key below to mint one and wire up the jwk / jku header automatically.

Generate attacker key (jwk / jku)

Mints an ephemeral keypair for this session, writes its private PEM into Private key PEM above, and sets Algorithm to RS256 (or ES256 for EC). With jwk it embeds the public key in the header; with jku it hosts a JWK Set at a Reqlore URL and points the header's jku at it — both the publish and any target fetch appear in History tagged jwt/jwks-host. Then press Sign. The hosted endpoint serves the public key only; the private key never leaves this page.

3. RS→HS key confusion

Paste the server's RSA public key. Reqlore signs the current token's payload with HS256 using the public-key bytes as the HMAC secret — a classic forgery when the server validates with the same key.

Accepts four formats — auto-detected: a PEM (-----BEGIN PUBLIC KEY-----), a single JWK ({"kty":"RSA","n":"…","e":"AQAB"}), a full JWKS document ({"keys":[…]}), or a https://target/.well-known/jwks.json URL (fetched through Reqlore's normal logged HTTP path — the GET appears in History tagged jwt/jwks-fetch). If the current token has a kid header, the matching JWKS entry is selected automatically; otherwise the first RSA key wins. Only http:// / https:// URLs are followed and redirects are disabled.
